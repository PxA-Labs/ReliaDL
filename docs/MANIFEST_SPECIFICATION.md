# ChunkGuard manifest specification Specification (v1.0)

> **Audience**: Systems Engineers, Security Auditors, Integration Developers
> **Status**: Specification Standard
> **Reading time**: ~15 minutes

---

## 1. Overview

The **ChunkGuard manifest specification (`.cgmanifest specification`)** is a cryptographically signed, machine-readable catalog that defines the chunking topology, cryptographic hashes, and mirror locations for a downloadable artifact. 

While ChunkGuard can operate in *ad-hoc mode* (deriving chunk boundaries from HTTP `HEAD` metadata and trusting hashes on first download), the **manifest specification Specification** provides:

1. **Pre-Authenticated Chunk Verification**: Every chunk's SHA-256 hash is known and cryptographically verified prior to downloading, eliminating "trust-on-first-download" risks.
2. **Merkle Tree Integrity**: Sub-chunk tree hashing enables immediate verification of partial streams before full chunk buffer completion.
3. **Multi-Source Failover & Mirroring**: Distributes chunk downloads across multiple CDN endpoints, cloud storage buckets, and peer mirrors.
4. **Supply-Chain Security & Provenance**: Cryptographic signatures (Ed25519 / RSA-PSS) guarantee the manifest specification was generated by an authorized publisher.
5. **Air-Gapped & Offline Verification**: Enables complete artifact verification in air-gapped environments without querying the origin server.

## 2. manifest specification File Format & Schema

### 2.1 File Encoding & Structure

* **File Extension**: `.cgmanifest specification` or `.cgmanifest specification.json`
* **Encoding**: UTF-8 without Byte Order Mark (BOM)
* **Format**: JSON (RFC 8259) or Canonical JSON (RFC 8785) when verifying signatures.

### 2.2 JSON Schema (Draft 2020-12)


## 3. Merkle Tree Root Hash Calculation

To enable single-root verification of entire chunk manifest specifications, ChunkGuard calculates a binary Merkle Tree over all chunk SHA-256 hashes:

```
                      [ Root Hash (R) ]
                             │
              ┌──────────────┴──────────────┐
       [ Node H(0,1) ]               [ Node H(2,3) ]
              │                             │
        ┌─────┴─────┐                 ┌─────┴─────┐
    [ Leaf 0 ]  [ Leaf 1 ]        [ Leaf 2 ]  [ Leaf 3 ]
    (Chunk 0)   (Chunk 1)         (Chunk 2)   (Chunk 3)
```

### Algorithm

1. **Leaf Nodes**: For each chunk $i \in [0, N-1]$:
   $$\text{Leaf}_i = \text{SHA-256}(0x00 \mathbin{\Vert} \text{chunk\_sha256}_i)$$
   *(Note: The `0x00` prefix prevents second-preimage attacks between internal nodes and leaves).*

2. **Internal Nodes**: For adjacent node pairs $(L, R)$:
   $$\text{Parent} = \text{SHA-256}(0x01 \mathbin{\Vert} L \mathbin{\Vert} R)$$

3. **Odd Number of Nodes**: If a level has an odd count, the solitary right-most node is duplicated or promoted up one level:
   $$\text{Parent} = \text{SHA-256}(0x01 \mathbin{\Vert} L \mathbin{\Vert} L)$$

4. **Root Hash**: The single top-level node hash becomes `merkle_tree_root`.

## 4. Digital Signature & Provenance

### 4.1 Canonical Signing Procedure

To sign a manifest specification:
1. Strip the `"signature"` block if present.
2. Canonicalize the remaining JSON document per [RFC 8785 (JSON Canonicalization Scheme - JCS)](https://datatracker.ietf.org/doc/html/rfc8785).
3. Compute the cryptographic signature over the canonical UTF-8 bytes:
   * **Ed25519**: `Ed25519Sign(private_key, canonical_bytes)`
   * **RSA-PSS**: `RSAPSSSign(private_key, SHA-256(canonical_bytes))`
4. Append the `"signature"` block containing `algorithm`, `key_id`, and `signature_hex`.

### 4.2 Verification Flow

```
[ Load .cgmanifest specification ] ──▶ [ Extract signature & public key ]
                                    │
                                    ▼
                      [ Strip signature block ]
                                    │
                                    ▼
                      [ JCS Canonicalize JSON ]
                                    │
                                    ▼
                      [ Verify Ed25519 / RSA-PSS ]
                         ├── [FAIL] Invalid ──▶ Raise manifest specificationSignatureMismatchError
                         └── [PASS] Valid   ──▶ Proceed with Verified Chunk Download
```

## 5. Multi-Source Mirror Resolution

When a manifest specification specifies multiple `mirrors`, ChunkGuard distributes chunk downloads across mirrors using priority and health weights:

```python
def select_mirror_for_chunk(chunk_index: int, mirrors: list[MirrorSpec]) -> str:
    """
    Selects optimal mirror based on priority ranking, worker load,
    and historical failure rates.
    """
    healthy_mirrors = [m for m in mirrors if m.is_healthy]
    # Sort by priority (1 = highest)
    sorted_mirrors = sorted(healthy_mirrors, key=lambda m: m.priority)
    return sorted_mirrors[chunk_index % len(sorted_mirrors)].url
```

If an HTTP 5xx or timeout occurs on mirror A for chunk $k$, the retry handler automatically switches to mirror B for the subsequent retry attempt.

## 6. CLI Operations for manifest specifications

### 6.1 Generate manifest specification

```bash
# Generate manifest specification for local file with 16MB chunk size
chunkguard manifest specification generate \
  --file "./dist/ubuntu-24.04-server.iso" \
  --chunk-size 16MB \
  --output "./dist/ubuntu-24.04-server.iso.cgmanifest specification" \
  --mirror "https://cdn1.example.com/ubuntu-24.04-server.iso" \
  --mirror "https://cdn2.example.com/ubuntu-24.04-server.iso"
```

### 6.2 Sign manifest specification

```bash
# Sign manifest specification using Ed25519 private key
chunkguard manifest specification sign \
  --manifest specification "./dist/ubuntu-24.04-server.iso.cgmanifest specification" \
  --private-key "~/.chunkguard/release_ed25519.key" \
  --key-id "release-2026-q3"
```

### 6.3 Download Using manifest specification

```bash
# Execute download driven completely by signed manifest specification
chunkguard download \
  --manifest specification "./dist/ubuntu-24.04-server.iso.cgmanifest specification" \
  --trusted-key "~/.chunkguard/release_ed25519.pub" \
  --output "/downloads/ubuntu-24.04-server.iso"
```

### 6.4 Verify manifest specification & Local File

```bash
# Verify an existing file against a signed manifest specification offline
chunkguard manifest specification verify \
  --manifest specification "./dist/ubuntu-24.04-server.iso.cgmanifest specification" \
  --file "/downloads/ubuntu-24.04-server.iso" \
  --trusted-key "~/.chunkguard/release_ed25519.pub"
```

## 7. Python SDK Integration

```python
from chunkguard.manifest specification import manifest specificationManager, Chunkmanifest specification

# Load and verify manifest specification
manager = manifest specificationManager(trusted_public_keys_dir="./keys")
manifest specification: Chunkmanifest specification = manager.load_and_verify("ubuntu.iso.cgmanifest specification")

print(f"Artifact: {manifest specification.artifact_metadata.filename}")
print(f"Total Chunks: {manifest specification.chunking_topology.total_chunks}")
print(f"Merkle Root: {manifest specification.chunking_topology.merkle_tree_root}")
print(f"Signature Validated: {manifest specification.is_signature_valid}")
```
